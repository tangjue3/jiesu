# jiesu

面向 AI Coding 用户的可视化前端编辑器：加载本地**真实运行**的网页，像设计工具一样编辑布局/样式/内容，并把改动**确定性地写回原始 React 源码**。

核心原则：**设计即代码，代码是唯一真实来源**——不做一次性产物导出，所有编辑最终落到开发者自己的 `.tsx` 文件里。

## 现在能做什么

打开本地 Vite 项目，按 `Alt+Shift+J`：

| 操作 | 结果 |
|---|---|
| 点元素 | 右侧属性面板显示该元素的**源码位置**（文件:行:列） |
| 改文本 / 间距 / 圆角 / 字号 / 颜色 / 布局 | 立刻写回 `.tsx`，页面热更新，**只动该动的那一行** |
| 按住元素拖动 | 元素跟手走，松手写 `translate-x-N`（**不写任何坐标**） |
| `Shift` + 拖动 | 调整同级顺序，落地是**移动 JSX 节点** |
| 点左侧「图层」 | 打开层级树，点行即选中画布元素 |
| 左下角「变更篮」 | 逐条查看、逐条撤销 |

改完继续用你自己的 AI Coding 工具开发，不冲突：我们改的就是你项目里的文件。

## 跑起来

```bash
cd jiesu
npm install
npm run build
npm run demo          # 起编辑服务 + 演示页面，Ctrl+C 退出
```

打开 `http://127.0.0.1:5273/`，`Alt+Shift+J` 进入选择模式。

接到自己的项目里：

```ts
// vite.config.ts —— 顺序不能反，jiesu 必须在 react() 之前
plugins: [jiesu(), react()]
```

## 一句话定位

同类产品（Onlook / v0 / Cursor Design Mode）都在往"Agent 代写代码"走。
jiesu 赌的是相反的一侧：**微调不该消耗 token，也不该改坏别的元素**——
所以核心是确定性编辑引擎，AI 只在确定性做不到时才兜底。

## 关键技术判断（都是实测出来的，不是推演）

| 判断 | 依据 |
|---|---|
| React 19 已彻底丢弃编译期 source | `_debugSource` / `props.__source` / `_debugInfo` 全为 null（S1） |
| 写回不能用 printer 全量重印 | 会吃掉模板字面量里 `${` 后的缩进，diff 从 1 行变多行（S2） |
| 单锚点定位会改错元素 | 上方加一行 → 行号整体 +1 → 下一次编辑打到别的元素（S3） |
| 布局编辑可以不产出绝对定位 | 5 种真实布局改造后产物零 `absolute`（S4） |
| `translate-*` 与 `absolute` 不是一回事 | 前者仍在 Flow 里，兄弟照常排版、断点照常生效（V0.4 策略修订） |
