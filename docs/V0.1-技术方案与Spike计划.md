## 0. 决策：三个痛点 → 三个最小能力（一条闭环）

"三个都要"不能理解为"三个都做深"。MVP 的做法是**一条最小闭环，每个痛点各配一个最小能力**：

| 痛点 | MVP 最小能力 | 做到什么程度 | 明确不做 |
|---|---|---|---|
| ① 找不到元素在哪 | **点选 + 组件栈 + 跳 IDE** | hover 高亮 → 点击选中 → 面包屑显示组件栈 → 显示 `file:line:col` → 一键打开 VS Code / Cursor | 全局搜索、依赖图谱 |
| ② 知道在哪但描述不清 | **结构化属性面板** | 文本 / 间距 / 颜色 / 字号 / 圆角 / 边框 六类，用控件而不是语言描述；布局类操作走 flex/grid 语义 | 自然语言改 UI、组件替换、AI 圈选 |
| ③ 改完 A 坏了 B | **变更篮** | 每条改动 = 一条可审阅记录（diff + 影响面标签），逐条撤销 / 批量丢弃 / 全部回滚 | 自动测试、视觉回归、AI 校验 |

**为什么必须一次打通三者**：单独的"定位"价值有限（`vite-plugin-code-inspector` 已经免费做到了），价值恰恰来自"定位 → 精确表达 → 安全落地"的串联。

## 1. ⚠️ 技术前提修正：React 19 没有 `_debugSource`

我在调研文档里建议的 L0 方案（零配置读 fiber `_debugSource`）**在 React 19 下不成立**，必须修正：

| 事实 | 来源 |
|---|---|
| React 18：`_debugSource` 在 host fiber 和 composite fiber 上都有（dev） | bippy 版本兼容表 |
| **React 19：`_debugSource` 仅保留在 composite fiber，host fiber 已移除**（dev） | bippy 版本兼容表 |
| React 19 新增 `_debugStack`（dev），但要填充它需把 `jsxImportSource` 指向 bippy 的运行时（要改用户 tsconfig） | bippy 文档 |
| 已有 `vite-plugin-react-fiber-source` 专门修复此问题：拦截 `react/jsx-dev-runtime`，把 source 注入 `_debugInfo`，支持 React 19.0.x / 19.2+ | npm 包说明 |
| `@vitejs/plugin-react`（babel）默认带 `@babel/plugin-transform-react-jsx-source`；`-swc` 走 `jsc.transform.react.development`；esbuild 走 `jsxDev` —— **三者 dev 都会发射 source** | package-lock 证据 + react-dev-inspector 文档 |
| 拦截 `react/jsx-dev-runtime` 这个 specifier 的方式，**babel 版与 swc 版官方插件都可用，React 17/18/19 都能拿到精确行列，生产构建不含相关代码** | click-and-review 进阶文档（实测结论） |

**结论【推断】**：不要把赌注押在 `_debugSource` 上。改走**编译期注入 DOM 属性**，理由：

1. 我们本来就要让用户装 Vite 插件（注入 overlay），编译期注入是**零额外安装成本**；
2. DOM 属性是**元素级**精度（`_debugSource` 只是组件级），正好满足"改这个 div 而不是那个 div"；
3. **跨 React 版本稳定**，不依赖 React 内部结构；
4. 顺带解决 HMR 后重新选中（id 稳定可重放）。

### 定案：Locator 三层降级

| 层 | 方案 | 触发条件 | 精度 |
|---|---|---|---|
| **L1（主）** | Vite 插件拦截 `react/jsx-dev-runtime`，包装 `jsxDEV`：对 host 元素注入 `data-jiesu-id`，并写入全局 registry `{id → file/line/column}` | 装了插件（默认） | **元素级，最精确** |
| **L2（兜底）** | 读 fiber `_debugSource` / `_debugStack`（React ≤18 直接可用） | 插件注入失效、或用非 Vite 场景 | 组件级 |
| **L3（兜底）** | CSS 选择器 + 组件栈 + 文本指纹匹配 | 前两层都失败 | 弱，**只用于"跳 IDE"，不用于写回** |

> **硬规则：只有 L1/L2 拿到的定位才允许写回代码；L3 只能用于跳转和查看。**【推断】

## 2. 技术选型

| 模块 | 选型 | 理由 | 备选 / 风险 |
|---|---|---|---|
| 定位注入 | Vite 插件 `transform` + 拦截 `react/jsx-dev-runtime` | 跨 React 版本、对 babel/swc 都有效 | 若拦截预打包 deps 不稳 → 退化为 babel plugin 注入（`react({ babel: { plugins: [...] } })`），需用户多配一行 |
| 浏览器覆盖层 | 原生 TS + **Shadow DOM** | 避免被页面 CSS 污染、避免污染页面 | Solid/preact 可选；MVP 用原生够 |
| 通信 | WebSocket（server ↔ overlay）+ HTTP POST（overlay → server） | 双向、HMR 后可推送重选指令 | — |
| AST 写回 | **recast + @babel/parser(recast/parsers-typescript)** | recast 最大程度保留原始格式与注释 → **diff 只有该变的那一行**，这是"改得准"的命门 | ts-morph（API 更友好但重排风险更高，且需 ts 编译） |
| className 解析 | 自研 tokenizer（识别 `hover:`/`md:`/`dark:` 前缀 + 按类别归组） | 不依赖 Tailwind 运行时，v3/v4 通用 | 后续可接 `@tailwindcss/oxide` 做候选合法性校验 |
| CSS 写回 | PostCSS（v0.2） | 改 `@theme` token / CSS 变量 | v0.1 只读 |
| 本地服务 | Node + `vite.createServer` 中间件模式 或独立 Fastify | 与 dev server 同进程最省事 | — |
| 打包 | tsup | 单包多入口（plugin / client / cli） | — |
| 回滚 | git（要求工作区干净）+ 变更记录落盘 `.jiesu/changes.json` | 最可靠 | 无 git 时退化为文件快照 |

**不做 monorepo**：MVP 用单包 `jiesu`，内部按 `src/core`（**禁止 import 任何 UI/DOM 代码**）/ `src/client` / `src/server` / `src/vite-plugin` 分层。等要单独发行内核时再拆。

## 3. 关键接口（把类型定下来 = 把架构定下来）

```ts
// 元素引用：定位的唯一产物
export interface ElementRef {
  id: string;                  // data-jiesu-id，稳定
  filePath: string;            // 绝对/相对项目根路径
  line: number; column: number;
  componentStack: string[];    // ['App', 'Hero', 'Card'] 用于面包屑 + HMR 后重选
  domPath: number[];           // 同类索引路径，HMR 后重放选中
  instanceCount: number;       // 同组件实例数 → 多实例警告
  locatorLevel: 'L1' | 'L2' | 'L3';
}

export type ChangeKind = 'text' | 'spacing' | 'color' | 'font' | 'radius' | 'border' | 'layout';

// 一次文件级编辑（recast 输出）
export interface FileEdit {
  filePath: string;
  start: number; end: number;      // 源码字符区间
  before: string; after: string;
}

// 变更篮里的一条
export interface Change {
  id: string;
  kind: ChangeKind;
  target: ElementRef;
  strategy: 'deterministic' | 'ai';
  summary: string;                 // "padding: p-4 → p-6"
  edits: FileEdit[];
  risks: Array<'multi-instance' | 'theme-level' | 'dynamic-class' | 'unresolved'>;
  createdAt: number;
}
```

**三条不可协商的规则**：
1. 任何写回必须先产出 `Change`（含 `FileEdit[]`），**禁止直接写文件**；
2. `strategy: 'ai'` 只允许在用户显式确认后出现，**禁止静默降级**；
3. 定位为 `L3` 时**禁止写回**。

## 4. 目录结构（MVP）

```
jiesu/
├── src/
│   ├── core/                 # 纯 TS，零 DOM/UI 依赖，可单测
│   │   ├── locator/          # L1 registry 解析 / L2 fiber / L3 fallback
│   │   ├── inspect/          # computed style → 结构化样式模型
│   │   ├── plan/             # 操作 → Change（不含 IO）
│   │   ├── write/            # recast writer：text / tailwind / inline
│   │   └── apply/            # 写文件 + 审计 + 回滚
│   ├── server/               # WebSocket + HTTP，持有 core
│   ├── client/               # 浏览器 overlay（Shadow DOM）
│   ├── vite-plugin/          # 注入 jsx-dev-runtime 包装 + client 脚本
│   └── cli/                  # npx jiesu
├── fixtures/                 # 靶场：真实 React+Tailwind 页面（S2/S4 用）
└── spikes/                   # 各 Spike 的可执行验证脚本
```

## 5. Spike 计划（先验证，再写产品）

> 排序原则：**能离线验证、风险最高的先做**。S2 是项目成立性的命门。

### S2（先做）｜AST 确定性写回 —— 纯 Node，无需浏览器

**做什么**：对 `fixtures/` 里的真实 TSX，把"某元素 `p-4` → `p-6`"变成一次 recast 编辑。

步骤：
1. 建 `fixtures/Hero.tsx` 等 5 个真实组件（含：静态 className、模板串、`cn()` 调用、条件样式、多处复用）
2. 实现 `writeTailwindClass(filePath, elementLoc, { category, from, to })`
3. 用 recast 打印，对比原始文件，断言 **diff 只有 1 行**

**通过标准**：
- 10 个用例中 ≥9 个 diff 干净（只动目标节点，格式/注释/其它代码零变化）
- 遇到 `cn()` / 动态拼接时**正确返回 `unresolved` 而不是瞎改**

**失败预案**：若 recast 格式保留不达标 → 换 ts-morph + 只重写目标节点的打印（`node.replaceWithText`），仍不达标则**降级为"AI 兜底 + 强制 diff 审阅"**，此时产品定位要下调。

### S1｜定位注入 —— 需 dev server，不需要浏览器

**做什么**：Vite 插件拦截 `react/jsx-dev-runtime`，验证注入生效且不污染生产构建。

步骤：
1. 最小 Vite+React+TS demo（React 19）
2. 插件实现两条路径，**先试 B，失败则 A**：
   - **B（首选）**：`resolveId`/`load` 返回包装模块，包装 `jsxDEV`：对 `typeof type === 'string'` 的元素注入 `data-jiesu-id` + 写 registry
   - **A（备选）**：`transform` hook 文本级改写预打包 deps 里的 `jsxDEV` 定义（参考 `vite-plugin-react-fiber-source`）
3. 用 `vite.createServer()` + `server.transformRequest('/src/App.tsx')` 检查产物里引入了包装模块（**不需要浏览器**）
4. `vite build` 后 grep 产物，断言**不含任何 jiesu 代码**

**通过标准**：React 19 + babel 插件 / React 19 + swc 插件 两种组合都能拿到 `file:line:col`；生产构建零残留。

### S3｜HMR 后重新选中 —— 需浏览器（可延后到 V0.1 中期）
用 `domPath + componentStack` 重放选中；连续 20 次改动不丢选中。

### S4｜布局语义不写坏 —— 纯 Node + fixture
对 flex/grid 容器做"改 direction / 改 order"，断言输出**不含任何 `position:absolute` / `left:` / `top:`**。
**通过标准**：导航、卡片列表、表单、Hero、侧边栏 5 种真实布局全部保持响应式。

- [ ] 所有改动落盘前要求 `git status` 干净

## 7. 用 AI Coding 开发本产品的自我约束

（否则我们就是自己踩自己要解决的坑）

1. **先写 golden test 再写实现**：`fixtures/原始.tsx` → `fixtures/期望.tsx`，让 AI 补 `core/write` 的实现，测试通过才算完成。
2. **`src/core` 禁止出现 DOM/UI 相关 import**，这条要写成 ESLint 规则让 AI 无法违反。
3. **不让 AI 自由发挥 UI 层**：overlay 的结构和交互由你定，AI 只填细节。
4. **每次让 AI 改动后必看 `git diff`**，diff 里出现预期外的文件改动就回滚 —— 这正是我们要替用户解决的问题。
