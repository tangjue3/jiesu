## 0. 决策：三个痛点 → 三个最小能力（一条闭环）

"三个都要"不能理解为"三个都做深"。MVP 的做法是**一条最小闭环，每个痛点各配一个最小能力**：

| 痛点 | MVP 最小能力 | 做到什么程度 | 明确不做 |
|---|---|---|---|
| ① 找不到元素在哪 | **点选 + 组件栈 + 跳 IDE** | hover 高亮 → 点击选中 → 面包屑显示组件栈 → 显示 `file:line:col` → 一键打开 VS Code / Cursor | 全局搜索、依赖图谱 |
| ② 知道在哪但描述不清 | **结构化属性面板** | 文本 / 间距 / 颜色 / 字号 / 圆角 / 边框 六类，用控件而不是语言描述；布局类操作走 flex/grid 语义 | 自然语言改 UI、组件替换、AI 圈选 |
| ③ 改完 A 坏了 B | **变更篮** | 每条改动 = 一条可审阅记录（diff + 影响面标签），逐条撤销 / 批量丢弃 / 全部回滚 | 自动测试、视觉回归、AI 校验 |

**为什么必须一次打通三者**：单独的"定位"价值有限（`vite-plugin-code-inspector` 已经免费做到了），价值恰恰来自"定位 → 精确表达 → 安全落地"的串联。

## 1. ⚠️ 技术前提修正：React 19 拿不到源码位置（已实测）

原方案（L0：零配置读 fiber `_debugSource`）**在 React 19 下不成立**，已在 S1 Spike 中实测确认：

| 探测项（React 19.3.1） | 结果 |
|---|---|
| `fiber._debugSource` | `null`（已移除） |
| `fiber._debugInfo` | `null` |
| `fiber.memoizedProps.__source` | `null`（props 里也没有） |
| `fiber._debugStack` | `"Error: react-stack-top-frame"`（无用） |
| `@vitejs/plugin-react` dev 产物 | **确实发射了 source**，但 React 19 直接丢弃 → 信息白烧 |
| 纯 esbuild `jsxDev: true` | **不发射 source**（`__source` 与 source 都没有） |

### 定案：编译期注入 DOM 属性（已实测通过）

既然运行时拿不到，就自己注入。Vite 插件在 `enforce: 'pre'` 阶段用 Babel 解析 TSX，给每个 JSX 元素写入位置：

```jsx
// 源码
<div className="p-4 text-white">
// dev 产物
jsxDEV("div", { "data-jiesu-src": "src/Card.tsx:3:4", "data-jiesu-id": "src/Card.tsx#0", className: "p-4 text-white", ... })
```

**已验证**：dev 产物含位置 ✓ ／ 生产构建零残留 ✓ ／ 运行时 `getAttribute('data-jiesu-src')` 直接读回 ✓。

**插件顺序要求**：`plugins: [jiesu(), react()]`。顺序反了会检测到 `jsxDEV(` 并报 `tooLate` + 警告，不会静默失败。

### ⚠️ 补充修正：单锚点不够，必须双锚点（S3 实测）

S3 Spike 暴露了一个**正确性缺陷**：写回代码会改变文件内容 → 后续元素的行号全部漂移。
原来的实现把 `line:column` 缓存死，**写回一次之后定位信息就全错了**，下一次改会打错元素。

解法是引入**第二个锚点**——结构锚点：

| 属性 | 内容 | 特性 |
|---|---|---|
| `data-jiesu-src` | `file:line:col` | 精确，但**会漂移** |
| `data-jiesu-id` | `file#0.1` | JSX 层级路径，**不漂移**（结构变了才失效） |

定位决策（**绝不猜**）：

| 情况 | 行为 |
|---|---|
| 两者指向同一元素 | ✅ 直接命中 |
| 只有结构锚点（行号漂了） | ✅ 用结构锚点 |
| 冲突 + 该行唯一 | ✅ 采信行号（用户真移动了元素） |
| 冲突 + 该行不唯一 | ❌ 明确拒绝：「元素位置已变化，请重新选择」 |
| 都没有 | ❌ 明确拒绝 |

**一致性前提**：注入的 id 与服务端定位必须由**同一份 JSX 树遍历算法**产出
（`src/core/locate/jsx-tree.ts`），否则 id 与定位对不上，交叉校验形同虚设。

### Locator 降级链（更新）

| 层 | 方案 | 状态 |
|---|---|---|
| **L1（主）** | 编译期注入 `data-jiesu-src` + `data-jiesu-id`（双锚点交叉校验） | ✅ **已实测通过（S1 + S3）** |
| L2 | fiber `_debugSource` / `_debugStack` | React ≤18 可用，React 19 不可用 |
| L3 | CSS 选择器 + 组件栈指纹 | 只许跳转，不许写回 |

> **硬规则：只有 L1/L2 拿到的定位才允许写回代码。**

### HMR 后的选中态保持（S3 已实测通过）

写回 → Vite HMR → React 重渲染会打断编辑循环。实测结论：

- **时序**：写文件 → 服务端广播（此时 DOM 还是旧的）→ Vite 侦测 → 编译推送 → React 重渲染。中间有**数百毫秒**。
- **策略**：轮询等待变化（延迟递增 60/120/250/400/700/1200ms）。节点被替换 → 用指纹找回；class 变了 → 刷新面板数值；都没变 → 继续等。
- **兜底**：`MutationObserver` 捕获**用户手动改代码**触发的 HMR（服务端无广播，只能靠 DOM 变化感知）。
- **元素指纹优先级**：稳定 id → 结构锚点 → 元素自身文本（仅唯一匹配时采用）。找不到就明说"元素已不存在"。
- **面板只更新数值、不重建 DOM**，避免打断用户正在进行的输入。

## 2. 技术选型

| 模块 | 选型 | 理由 | 备选 / 风险 |
|---|---|---|---|
| 定位注入 | Vite 插件 `enforce: 'pre'` + Babel 解析 TSX，在 JSX 标签注入 `data-jiesu-src` | 元素级、跨 React 版本稳定、不依赖 React 内部 API | 需 `plugins: [jiesu(), react()]` 顺序；dev 模式 DOM 多一个属性 |
| 浏览器覆盖层 | 原生 TS + **Shadow DOM** | 避免被页面 CSS 污染、避免污染页面 | Solid/preact 可选；MVP 用原生够 |
| 通信 | WebSocket（server ↔ overlay）+ HTTP POST（overlay → server） | 双向、HMR 后可推送重选指令 | — |
| **AST 写回** | **@babel/parser 定位 + 源码字符区间 splice** | **格式 100% 保真，diff 只动目标那一行**（已实测） | ❌ 不用 recast 打印：模板字面量会丢换行缩进 |
| className 解析 | 自研 tokenizer（识别 `hover:`/`md:`/`dark:` 前缀 + 按类别归组） | 不依赖 Tailwind 运行时，v3/v4 通用 | 后续可接 `@tailwindcss/oxide` 做候选合法性校验 |
| px ↔ 类换算 | 间距基数 4px（v3/v4 一致）；圆角刻度单独映射 | 面板给 px、代码写类名，必须有桥 | 无法映射到离散刻度时明确拒绝 |
| CSS 写回 | PostCSS（v0.2） | 改 `@theme` token / CSS 变量 | v0.1 只读 |
| 本地服务 | Node + `vite.createServer` 中间件模式 或独立 Fastify | 与 dev server 同进程最省事 | — |
| 打包 | tsup | 单包多入口（plugin / client / cli） | — |
| 回滚 | git（要求工作区干净）+ 变更记录落盘 `.jiesu/changes.json` | 最可靠 | 无 git 时退化为文件快照 |

**不做 monorepo**：MVP 用单包 `jiesu`，内部按 `src/core`（**禁止 import 任何 UI/DOM 代码**）/ `src/client` / `src/server` / `src/vite-plugin` 分层。等要单独发行内核时再拆。

## 3. 关键接口（把类型定下来 = 把架构定下来）

```ts
// 元素引用：定位的唯一产物
export interface ElementRef {
  id: string;                  // data-jiesu-id，稳定
  filePath: string;            // 绝对/相对项目根路径
  line: number; column: number;
  componentStack: string[];    // ['App', 'Hero', 'Card'] 用于面包屑 + HMR 后重选
  domPath: number[];           // 同类索引路径，HMR 后重放选中
  instanceCount: number;       // 同组件实例数 → 多实例警告
  locatorLevel: 'L1' | 'L2' | 'L3';
}

export type ChangeKind = 'text' | 'spacing' | 'color' | 'font' | 'radius' | 'border' | 'layout';

// 一次文件级编辑（recast 输出）
export interface FileEdit {
  filePath: string;
  start: number; end: number;      // 源码字符区间
  before: string; after: string;
}

// 变更篮里的一条
export interface Change {
  id: string;
  kind: ChangeKind;
  target: ElementRef;
  strategy: 'deterministic' | 'ai';
  summary: string;                 // "padding: p-4 → p-6"
  edits: FileEdit[];
  risks: Array<'multi-instance' | 'theme-level' | 'dynamic-class' | 'unresolved'>;
  createdAt: number;
}
```

**三条不可协商的规则**：
1. 任何写回必须先产出 `Change`（含 `FileEdit[]`），**禁止直接写文件**；
2. `strategy: 'ai'` 只允许在用户显式确认后出现，**禁止静默降级**；
3. 定位为 `L3` 时**禁止写回**。

## 4. 目录结构（MVP）

```
jiesu/
├── src/
│   ├── core/                 # 纯 TS，零 DOM/UI 依赖，可单测
│   │   ├── locator/          # L1 registry 解析 / L2 fiber / L3 fallback
│   │   ├── inspect/          # computed style → 结构化样式模型
│   │   ├── plan/             # 操作 → Change（不含 IO）
│   │   ├── write/            # recast writer：text / tailwind / inline
│   │   └── apply/            # 写文件 + 审计 + 回滚
│   ├── server/               # WebSocket + HTTP，持有 core
│   ├── client/               # 浏览器 overlay（Shadow DOM）
│   ├── vite-plugin/          # 注入 jsx-dev-runtime 包装 + client 脚本
│   └── cli/                  # npx jiesu
├── fixtures/                 # 靶场：真实 React+Tailwind 页面（S2/S4 用）
└── spikes/                   # 各 Spike 的可执行验证脚本
```

## 5. Spike 计划（先验证，再写产品）

> 排序原则：**能离线验证、风险最高的先做**。S2 是项目成立性的命门。
> **执行结果见 `Spike报告-S1与S2.md`：S1 ✅ S2 ✅，21/21 用例通过。**

### S2 ✅ 已完成｜AST 确定性写回 —— 纯 Node，无需浏览器

**结论**：**AST 只用于定位，落地靠源码字符区间 splice**（不是"改 AST 再整体打印"——recast 重印模板字面量会丢换行缩进，diff 会从 1 行变多行）。

已验证 8 类形态：静态 className / 跨行模板字面量 / `cn()` 调用（拒绝）/ 条件表达式（拒绝）/ 多实例 / inline style / JSX 文本 / 同类别多类。

**通过标准**：10 个用例中 ≥9 个 diff 干净 —— ✅ 达成（8/8 形态 + 4 个分类器用例）。

### S1 ✅ 已完成｜定位注入 —— Vite 真实管线 + jsdom 运行时

**结论**：React 19 已丢弃所有运行时源码位置（实测），改为**编译期注入 `data-jiesu-src`**。

**通过标准**：dev 产物含位置 ✓ ／ 生产构建零残留 ✓ ／ 运行时 DOM 可读回 ✓。

### S3｜HMR 后重新选中 —— 需浏览器（可延后到 V0.1 中期）
写回是**同行替换 → 行号稳定**，用"组件栈 + 同类索引"做二级定位；连续 20 次改动不丢选中。

### S4 ✅ 已完成｜布局语义不写坏 —— 纯 Node + fixture
**结论**：可以在**不产出任何绝对定位**的前提下完成真实布局调整。

核心设计：① 族模型（一个布局属性 = 一个类族，只动同族 token）② 前置条件校验（容器类型不对 / 族不存在 → 拒绝）③ 安全闸（产物审计绝对定位，命中即拒）④ 结构级重排（移动 JSX 节点而非加 order 类，空白段固定不动 → 缩进 100% 保留）。

**通过标准**：5 种真实布局（导航栏 / 卡片网格 / 表单 / Hero / 侧边栏）全部保持响应式 —— ✅ 达成（11 个用例，含断点变体与拒绝路径）。详见 `Spike报告-S4-布局语义.md`。

## 7. 用 AI Coding 开发本产品的自我约束

（否则我们就是自己踩自己要解决的坑）

1. **先写 golden test 再写实现**：`fixtures/原始.tsx` → `fixtures/期望.tsx`，让 AI 补 `core/write` 的实现，测试通过才算完成。
2. **`src/core` 禁止出现 DOM/UI 相关 import**，这条要写成 ESLint 规则让 AI 无法违反。
3. **不让 AI 自由发挥 UI 层**：overlay 的结构和交互由你定，AI 只填细节。
4. **每次让 AI 改动后必看 `git diff`**，diff 里出现预期外的文件改动就回滚 —— 这正是我们要替用户解决的问题。
