# V0.5 结构编辑（插入 / 删除 / 复制）

> 内核在 S5 里已证明"插入节点成立"。这一版补的是**用户手上那一半**：
> 面板里有入口、点了之后不会改错元素、落地之后选中态跟着走。
> 验证：`spikes/v05` 5 个端到端用例，全量 177/177 通过。

## 一、面板上多了什么

```
结构
本元素   [复制] [删除]
插入     [基础 · 标题 ▾]
         [上方] [下方] [内部]
```

- **复制**：把当前元素整段 JSX 复制一份插到它后面（画布的 `Cmd+D`）
- **删除**：从源码里拿掉，独占一行时连换行一起删，不留空行
- **插入**：选一个组件模板，插到当前元素的同级上方 / 同级下方 / 内部末尾

组件模板在 `src/core/library/components.ts`，共 9 个（标题 / 段落 / 按钮 / 输入框 / 徽章 / 卡片 / 分隔线 / 双列栅格 / 纵向堆叠）。

> **模板就是一段可插入的 JSX，不是 JSON schema。**
> 这是「画布即代码」的直接结果：拖一个组件进来 = 往用户的 TSX 里插一段真实代码，
> 没有"导出"这一步，所以也不存在"生成出来的代码和画布不一致"。

模板有三条硬约束（由 `core/write/structure.ts` 强制）：
1. 必须**单根** JSX（多根无法确定插入边界）
2. 不能带 `import`——只能用用户项目里已有的标签与 Tailwind 类
3. 不能含业务逻辑——插进去的是可继续用鼠标编辑的静态结构

## 二、为什么插入时必须锁住整个结构区

这不是交互礼貌，是**正确性**问题。

S5 实测到的现象：

```
插入前： <section> 是 main 第 2 个子元素 → 锚点 0.1、第 5 行
插入后： 新按钮占走 0.1（第 5 行），<section> 被挤到 0.2（第 6 行）
```

如果插入后立刻再发一次编辑、而客户端还拿着旧定位，那么：

> **锚点 0.1 与第 5 行会一致地指向刚插入的按钮** —— 双锚点交叉校验此时的回答是
> 「完全可信」，而它是错的。

所以这一版的做法是：

| 阶段 | 行为 |
|---|---|
| 发出结构编辑 | 立刻上锁：结构按钮全部禁用，任何属性修改被拒绝并提示「上一次结构改动还在落地」 |
| 服务端返回 `changeApplied` + `select` | 客户端开始轮询目标元素（插入 → 新节点，删除 → 父节点） |
| HMR 落地、目标出现 | 选中它、从 DOM 重读锚点、解锁 |
| 8 秒仍未出现 | 解锁并明说「页面上没找到目标元素（可能被条件渲染挡住）」 |

**不猜**：找不到就说找不到，绝不把选中态停在一个可能已被别的元素占用的旧位置上。

一个细节：同一个源码元素在页面上可能有多个实例（列表渲染）。结构编辑后优先选**离原选中位置最近**的那个实例，用户才不会觉得"元素跳走了"。

## 三、端到端验证了什么

| 用例 | 断言 |
|---|---|
| 面板入口 | 复制 / 删除 / 上方 / 下方 / 内部 五个按钮都存在且可用 |
| 插入期间 | 结构按钮全部 `disabled`；此时改数值被拒，toast 含「还在落地」 |
| 落地后选中态 | 面板显示的源码位置**等于**新元素自己的 `data-jiesu-src`；随后改内边距，改到的是新元素那一行，其它行不动 |
| 删除 | 页面与源码同时消失、不留空行、选中态退回父元素 |
| 无 JS 错误 | 忽略 favicon/404 |

## 四、当前限制

| 限制 | 说明 |
|---|---|
| 只能插到**已有元素**的旁边或内部 | 往空页面插入第一个元素还没有入口（需要"新建项目"这条路，属于 A0 剩下的脚手架工作） |
| 不支持跨容器拖拽 | 移动节点到另一个容器需要 `moveChild`（删原节点 + 目标插入），未实现 |
| 插入位置只有前 / 后 / 末位 | 没有"插到第 n 个之前"的 UI |
| 模板不含业务逻辑 | 插进去的是静态结构；要交互得回代码里写 |
| 与同级内容挤在一行的元素 | 明确拒绝插入并要求先拆行（缩进无法判断） |
| 循环 / 条件渲染里的元素 | 插入会改**组件定义**，所有实例一起变；目前不额外警告，靠 `select` 定位到最近实例 |
