# 界塑｜可视化前端开发工具（UI 参考图与开发说明）

> 版本：视觉方案 V2（2026-10-26）  
> 产品名称：**界塑**（当前工作名称，可调整）  
> 文档用途：交给 AI Coding Agent，作为产品定位、页面结构、视觉统一规范和分阶段实现的基础。  
> **重要：本文件夹中的 PNG 是高保真概念参考图，不是可直接运行的页面，也不是精确尺寸的 Figma 源文件。** 图片中的微小文案、数据、图标以本文规范为准。

## 1. 产品定位

界塑是一款**面向所有 AI Coding 用户的独立可视化前端开发产品**，不是一个普通的静态页面生成器，也不是完整复刻 Figma。核心理念是：

**AI 生成真实前端代码 → 界塑打开并呈现真实页面 → 用户像操作画布一样拖入组件、选中元素、修改位置/大小/样式、调整设备适配 → 安全地将变化同步回代码。**

同时支持从空白画布创建页面，不强制先有 AI 生成的项目。重点解决用户“不容易通过文字提示词精确控制前端视觉效果”的问题。

目标用户包括个人开发者、AI Coding 用户、产品设计者、前端开发者和小团队。中文优先。第一阶段侧重 **Web/React 项目**，对 Vue 等其他框架预留扩展能力，但不要承诺第一版就可无损编辑任意网站。

## 3. 全局视觉规范：必须统一

### 3.1 整体风格

- 清爽、专业、成熟、简约高级；浅色界面，拒绝大面积黑色和夸张的 AI 机器人元素。
- 背景 `#F7F9FC`，面板 `#FFFFFF`，边框建议 `#E8ECF3`。
- 主强调色 `#5276F5`；次级点缀柔和紫 `#A78BFA`、薄荷绿 `#64CDB4`。点缀色不能喧宾夺主。
- 主文字建议 `#1F2937`，次级文字约 `#64748B`。实际对比度要满足可读性要求。
- 常规卡片、输入框统一轻描边和 **12px** 圆角，主按钮高度约 **40px**，避免过度阴影。
- 使用一致的中文无衬线字体栈：`Inter, PingFang SC, Microsoft YaHei, system-ui, sans-serif`；确保跨 Mac/Windows 合理回退。

### 3.2 固定应用框架（所有页面一致）

1. **最左侧全局导航栏固定宽度约 72px**，纯白底色，整页通高。
2. 顶部是同一个蓝色几何六边形/折带式 Logo 和“界塑”字样。实现时应使用一个复用 SVG/组件，不从各张 PNG 重新裁切不同 Logo。
3. 菜单图标、文字位置和顺序固定为：**首页、项目、画布、组件、样式、适配、AI、代码**；底部固定**设置**。只有当前项高亮蓝色浅底，其他项不移动。
4. **顶部全局工具栏约 60px**，统一面包屑位置、搜索框高度、通知图标和头像大小。各页只改变面包屑及业务工具。
5. 正文基础字号约 **13–14px**；导航标签约 **11–12px**；区块标题约 **16–18px**；标准页面标题约 **26px**。首页欢迎语可使用大号展示标题，但同层级页面标题不能随意变化。
6. 采用 **统一的 8px 间距体系**（常用 8/16/24/32px）。保持栅格、边框、图标线宽、状态色和悬停反馈一致。
7. 全局操作、组件卡片、弹窗、属性输入框、Tabs、图标按钮应封装为复用组件，不得每页重新造一套。

### 3.3 布局原则

- 设计稿目标截图比例是 16:9 宽屏桌面软件；实际产品需要支持常见桌面窗口缩放，不能写死为截图像素。
- 窄左导航与顶栏是**全局壳**；内部的“图层树、筛选栏、AI 对话栏、属性检查器”等属于**当前页面的局部面板**，可折叠或调整宽度。
- 画布和响应式页面要优先保留中心工作面积；必要时左右面板可收起。
- 按钮、选中边框、对齐线、变更高亮等交互状态，全部使用相同品牌蓝与状态色。

## 4. 七个页面的功能说明

### 01 项目首页

- 三个主要入口：**创建空白画布 / 导入现有项目 / 连接 AI Coding**。
- 最近项目展示项目名、封面缩略图、技术栈、最后修改时间；提供打开、重命名和项目设置入口。
- 从模板开始：营销落地页、SaaS 管理后台、个人作品集、企业官网。
- 进入项目后，应能切换到画布、组件、样式、适配、AI 精修与代码同步。

### 02 自由画布工作台——产品核心

- 中央是**可平移、缩放、带标尺/参考线/吸附提示的无限画布**。
- 左侧：可搜索的 UI 组件库与图层树。支持拖入文本、按钮、输入框、图片、卡片、导航、布局容器等。
- 画布元素可选择、移动、调整大小、复制、删除、分组及改变层级；支持撤销/重做、多选、键盘快捷键。
- 右侧属性面板：位置、尺寸、边距、字体、颜色、圆角、边框、阴影、布局和响应式约束。
- **核心技术原则**：普通 Web 布局优先通过 Flexbox / Grid / 约束表示，不应为所有元素都粗暴设置绝对定位；拖拽时要提供合法布局反馈。
- 既能设计新页面，也能映射并编辑已导入的真实前端项目。

### 03 UI 组件资源中心

- 内置按钮、表单、导航、标签、卡片、弹窗、统计展示、Hero 区块等组件。
- 搜索、分类筛选、实时预览、收藏、添加到画布。
- 组件要有可编辑属性、状态（默认/悬停/禁用等）和响应式行为；不仅是不可编辑截图。
- 允许导入项目内部组件；组件识别不稳定时明确提示兼容范围。

### 04 样式库与设计系统

- 管理品牌色、中性色、字体样式、圆角、间距、阴影、主题预设。
- 支持设计令牌（Design Tokens）与组件变体，例如 Button / Primary / Hover / Disabled。
- 修改全局令牌时提供影响预览，并让用户选择作用范围。
- 设计系统值应被多个页面和组件共享，不应只是单页静态面板。

### 05 多设备响应式适配

- 同一工作区并排放置**桌面 1440 / 平板 768 / 手机 390** 三种画板；可新增自定义宽度与断点。
- 支持各设备预览、跨断点选择同一元素、修改布局规则、隐藏/显示、覆写局部样式。
- 修改桌面布局时不应简单按比例压扁手机画面；应采用真实 CSS 媒体查询、容器查询或布局约束，实现内容重排。
- 需要清楚显示“全局样式”与“当前断点覆写”的区别，避免误操作影响所有设备。

### 06 AI 视觉精修

- 用户可框选真实页面区域并描述：例如“标题更醒目、按钮更突出、卡片间距增大”。
- 生成修改提案后显示**修改前 / 修改预览**，列出影响的元素和属性。
- 用户可逐项接受、全部应用、重新生成或撤销；**不得在未确认时自动覆盖代码**。
- 优先生成结构化编辑指令（例如修改 token、props、className），复杂变更才进入代码补丁流程。

### 07 代码同步与版本

- 打开项目时识别本地文件、分支状态、技术栈与支持程度。
- 可视化操作须与真实源码建立可追踪映射，显示文件及差异（diff）。
- 修改前进行预览、类型检查/构建检查（适用时）、受影响文件汇总、确认写入。
- 保留可恢复的编辑记录，支持撤销、回退与导出补丁；尊重用户现有未提交的 Git 更改，避免覆盖。
- **风险重点**：无法确定组件与源码映射时，必须提示“不支持直接安全回写”并采用受控方案，而非盲目覆盖 JSX/CSS。

## 5. 推荐的真实实现方向（允许 Agent 提出更合理方案）

- 前端应用：TypeScript + React，基于组件化路由结构与统一样式令牌实现七页。
- UI：适合桌面专业工具的轻量组件库；可以用 Tailwind CSS 等实现，但设计令牌必须集中维护。
- 画布：画板/选区/拖拽/缩放的交互层，与真实网页预览层分离；可使用 iframe 隔离运行中的网页。
- 状态：统一项目模型、页面模型、组件树、设计令牌、设备断点、编辑命令历史；支持撤销/重做。
- 代码：采用解析 AST（React JSX/TSX）、组件元数据或构建期标记完成“元素 ↔ 源码位置”映射；不能仅靠 DOM 坐标猜测文件位置。
- 本地项目接入：网页端可考虑浏览器文件授权 + 本地开发服务；若需要完整文件系统与开发命令集成，评估 Tauri/Electron 或本地桥接服务。**先明确权限与安全边界再选方案。**
- 安全：真实应用预览隔离、限制脚本权限、写文件前确认、备份或快照、不在未确认情况下执行危险命令。

以上为技术建议，**不是已经确定的不可更改技术栈**。Agent 应先给出可行性和架构评估，再确定核心依赖，避免日后大规模重写。

## 6. 分阶段实施要求

### 阶段 A：统一应用骨架与七页可运行 UI

1. 创建统一 `AppShell`、Logo、全局导航、顶部栏与样式令牌。
2. 完成七页路由、页面布局、局部面板、操作按钮及统一交互反馈。
3. 使用可替换的模拟数据构建组件卡、项目卡、代码 diff 样例，保持视觉接近本文件夹参考图。
4. 适配桌面不同窗口大小，确保未出现横向溢出或界面严重遮挡。

**验收**：七页导航可用、侧边栏和 Logo 全程不跳动、字号/色彩一致，所有页面均有基本可交互状态，不存在只有图片的假界面。

### 阶段 B：真正可用的可视化画布

1. 完成空白项目、画板、组件拖入、选中/移动/缩放、层级树、右侧属性修改。
2. 实现对齐辅助线、吸附、撤销/重做、缩放平移、复制粘贴、快捷键。
3. 建立设计令牌、组件库与画布元素之间的真实数据关联。
4. 让 1440/768/390 画板展示同一页面的不同响应式布局。

**验收**：用户可不写代码制作一个完整的、具有布局约束的简单响应式页面，并再次打开继续编辑。

### 阶段 C：AI Coding 项目接入与代码回写

1. 先选定有限且常用的受支持项目范围，如 React + TypeScript + 明确约定的组件结构。
2. 完成项目导入、运行预览、组件定位、编辑映射、代码补丁生成、diff 审核与确认写回。
3. 给不支持的语法、第三方复杂组件和无法追踪的样式提供明确降级行为。
4. 加入必要的构建/类型验证、快照恢复、异常处理与回归测试。

**验收**：在受支持的真实 React 项目中，画布里移动/修改一个按钮后，用户可以看到正确文件 diff，确认写入后项目正常运行，撤销时能够恢复原样。

### 阶段 D：AI 视觉精修和成熟化

- 区域选择 + 语言描述 → 结构化变更建议 → 前后预览 → 确认应用。
- 完善组件资源、模板、快捷键、协同能力、错误处理与性能优化。
- 在稳定基础上扩展 Vue、复杂组件、桌面封装或团队功能。

## 7. 开发 Agent 的执行指令

请先仔细阅读本文，并按编号审阅 `images/` 下全部 7 张图。**不要把 PNG 直接用作页面背景或假 UI**，需要编写真实组件和可操作的交互。

在动手前先交付：

1. 对产品定位及关键难点的简明复述，尤其是“画布编辑与代码双向同步”。
2. 合理的技术架构和项目目录建议，以及尚未确定但会影响架构的关键问题。
3. 按阶段 A→D 的执行清单与验收策略。

得到确认后先完成**阶段 A**，以 02 画布工作台为重点验证复用组件体系。开发中保持设计系统统一，不得为了单页效果随意改动全局 Logo、导航尺寸、字体或颜色。涉及删除、覆盖原项目代码、执行未知脚本等风险操作必须先征得用户确认。

### 不可偏离的产品原则

- **画布是真正可编辑的，不只是截图预览。**
- **组件库可拖入画布并继续编辑属性。**
- **页面支持多设备宽度与真实响应式规则。**
- **可视化更改必须有可审查、可恢复的代码同步路径。**
- **七页必须共用统一视觉体系和全局导航。**
- 优先做成熟、可靠、可扩展的实用产品，避免只做展示型 Demo。
