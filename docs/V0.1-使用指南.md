# jiesu 使用指南（V0.1 外壳 + V0.2 拖拽重排）

> 用真实 Chrome 打开真实页面、用鼠标点一次、改一次真实源码——这条链路已经端到端验证通过。

---

## 一、这是什么

jiesu 加载你**正在运行的真实网页**，让你像用 Figma 一样用鼠标编辑界面，而每一次修改都**确定性地写回你的源码文件**。

它的三条纪律，也是它与"AI 改代码"的根本区别：

| 纪律 | 含义 |
|---|---|
| **AST 只定位，splice 才落地** | 你拖 8px，代码里就只多了 8px；格式、注释、其它一行不动 |
| **改不了就明说** | 动态 className（`cn()`、条件表达式）会明确报错，绝不猜着改 |
| **写回前先产出变更计划** | 每条改动都是可审阅、可撤销、可批量丢弃的一条记录 |

---

## 二、三步接入

### 1. 安装并启动

```bash
npx jiesu
```

它会在项目里写一个 `.jiesu/server.json`（记录端口），并启动本地 WebSocket 服务。

### 2. 在 vite.config.ts 里加插件

```ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import { jiesu } from 'jiesu';

export default defineConfig({
  plugins: [jiesu(), react()],   // ← jiesu 必须在 react() 之前
});
```

> **顺序很重要**：jiesu 需要在 JSX 被编译**之前**注入源码位置。
> 顺序写反了会看到警告「注入时机太晚：JSX 已被编译」，不会静默失败。

### 3. 启动你的开发服务器

```bash
npm run dev
```

打开页面，按 **Alt+Shift+J** 进入选择模式。

## 三、怎么用

| 操作 | 效果 |
|---|---|
| `Alt+Shift+J` | 进入 / 退出选择模式 |
| 移动鼠标 | 高亮目标元素，角标显示 `文件:行:列` |
| 点击元素 | 右侧打开属性面板，显示该元素的源码位置 |
| 改面板里的数值 | 立刻写回源码文件，页面热更新 |
| **直接拖动已选元素** | **元素跟着鼠标走**，松手写 `translate-x-N` / `translate-y-N` |
| **`Shift` + 拖动** | 调整它在同级中的顺序（移动 JSX 节点） |
| `Esc`（拖拽中） | 取消这次拖动，代码一个字都不改 |
| `Alt+Shift+L` | 展开 / 收起左侧图层面板 |
| 点图层里的行 | 选中该元素（与在画布上点等价） |
| `Esc` | 取消拖拽 / 退出选择模式 / 关闭面板 |
| 左下角「变更篮」 | 列出本次会话的所有改动，可逐条撤销 |

属性面板目前提供：**文本内容**、**间距**（内外边距 / gap）、**圆角**、**字号**、**颜色**（预设色 + 任意 `#rrggbb`）、**布局**（排列方向 / 对齐 / 分布）、**位移**（X / Y + 复位）、**结构**（复制 / 删除 / 插入组件）。

### 结构：插入、删除、复制

面板底部有「结构」区：

- **复制**：把当前元素整段复制一份插到它后面
- **删除**：从源码里拿掉（独占一行时连换行一起删，不留空行）
- **插入**：选一个组件模板（标题 / 段落 / 按钮 / 输入框 / 徽章 / 卡片 / 分隔线 / 双列栅格 / 纵向堆叠），插到当前元素的**上方**、**下方**或**内部**

插入期间整个结构区会被锁住几秒——这是必须的：插入会重排同级元素的锚点，此时再发编辑会打错元素（详见 `V0.5-结构编辑.md`）。落地之后选中态自动变成新插入的那个元素，接着改属性改的就是它。


### 拖动：跟手，但不写坐标

拖动会真的移动元素，但你**不会**在代码里看到 `left: 240px` 这种东西：

```jsx
// 拖动之前
<button className="rounded-md bg-blue-600 px-4 py-2 text-white">
// 往右下拖了 88 / 36 像素之后
<button className="rounded-md bg-blue-600 px-4 py-2 text-white translate-x-22 translate-y-9">
```

位移吸附到 4px 刻度，所以是 `translate-x-22` 而不是 `translate-x-[87.4px]`。
元素**仍在文档流里**：兄弟元素照常排版，断点布局照常生效——这正是它和 `position: absolute` 的本质区别（后者永久禁止）。

Shift + 拖动则走另一条路：调整同级顺序，落地是**移动 JSX 节点**，连 `order` 类都不写。

### 图层面板怎么用

页面左侧竖排的「图层」标签点开就是层级树（每行显示 `标签.类名` + 文本片段）。

- 点某一行 → 画布上对应元素被选中，右侧属性面板同步打开；
- 在画布上点元素 → 树自动展开祖先、高亮那一行；
- 悬停某一行 → 画布上预览高亮（不会改变选中）；
- 半透明的行表示该元素**没有源码位置**（多来自第三方库），点它只会提示，不会改写。

**默认是收起的**：这个页面不是我们的画布，面板一展开就会盖住左侧内容，不该默认挡着你。

### 调整同级顺序怎么用

1. 先点一下选中要移动的元素（比如三张卡片里的第一张）；
2. **按住 `Shift`** 再拖它，会看到一条橙色插入线告诉你**松手后会插到哪**；
3. 松手 —— 源码里这几个节点的顺序真的变了，页面同时热更新；
4. 选中态不会丢，可以接着拖、接着改。

**它不会写任何 `position / left / top`，连 `order-N` 都不写**：改的是 flex / grid 容器的子节点顺序，产物依然是响应式的。
遇到不支持的场景会明确告诉你原因（父容器不是 flex/grid、跨容器拖、容器里有条件渲染等），不会硬改。

## 四、它凭什么敢直接改你的文件

### 1. 每个元素都带着自己的"地址"

Vite 插件在 dev 模式下给每个 JSX 元素注入 `data-jiesu-src="src/App.tsx:8:5"`：

```jsx
// 你写的
<nav className="flex items-center gap-4 px-6 py-4">
// dev 管线产出
jsxDEV("nav", { "data-jiesu-src": "src/App.tsx:8:5", className: "flex items-center gap-4 px-6 py-4", ... })
```

React 19 已经移除了 `_debugSource` / `props.__source`，运行时拿不到任何源码位置（见 `Spike报告-S1与S2.md` 的实测），所以**必须自己注入**。
生产构建零残留——插件只在 `serve` 模式生效。

每个元素同时带**两个锚点**：

| 锚点 | 形式 | 特点 |
|---|---|---|
| 行号锚点 | `data-jiesu-src="src/App.tsx:8:5"` | 精确，但写回会让行号漂移 |
| 结构锚点 | `data-jiesu-id="src/App.tsx#0.1"` | JSX 层级路径，写回后不变（见 `Spike报告-S3-HMR重绑定.md`） |

两者交叉校验：一致才写回；只有一处能对上就用它；两处冲突且无法消歧 → **明确拒绝**，绝不猜。

### 2. 改一个值，文件里只动一行

改写不是"改 AST 再整体打印"，而是**算出要替换的字符区间，然后精确替换**：

```diff
- <nav className="flex items-center justify-between gap-4 px-6 py-4">
+ <nav className="flex items-center justify-between gap-12 px-6 py-4">
```

### 3. 布局改动不会写出绝对定位

布局编辑改的是**布局本身**（flex 方向、对齐、分布、网格跨度、gap、JSX 节点顺序），
并且有一道安全闸：写回后立刻审计产物，一旦出现 `absolute` / `left-*` / `position:` 之类就**拒绝这次改动**。

拖拽重排走的是同一条路：**移动 JSX 节点**，而不是加 `order-N` 类，更不是写坐标。
加 `order` 会让文档顺序与视觉顺序脱节（SSR、无 JS、读屏全错），所以我们宁可改结构。

### 4. 当前值来自代码，不是来自渲染结果

面板显示"间距 12px"时，读的是 class 里的 `gap-3`（3 × 4px），**不是** computed style。
即使你的项目还没装 Tailwind、或样式被覆盖，数值依然正确——因为**代码才是唯一真实来源**。

## 五、当前限制

| 限制 | 说明 |
|---|---|
| 只支持 React + Vite | Next.js / Vue / Svelte 尚未支持 |
| 只认 Tailwind 类 | 未装 Tailwind 的项目可以定位与改文本，但样式类改不了 |
| 动态 className 改不了 | `cn()` / 条件表达式 → 明确拒绝（可后续接 AI 兜底） |
| 只有文本/间距/圆角/颜色/字号/布局/顺序 | 组件替换、图片替换、自由定位都还没有 |
| 图层只有 DOM 层 | 看不到 `<Card />` 这类组件节点；无搜索/过滤 |
| 撤销基于文本片段 | 同一片段出现多次时会拒绝回滚并提示手动处理 |
| 拖拽只支持同级重排 | `Shift`+拖；跨容器拖、父容器不是 flex/grid、容器内含条件渲染或循环子项 → 明确拒绝 |
| 位移只到 4px 粒度 | 吸附到 Tailwind 刻度，不写 `translate-x-[87.4px]` 这类任意值；无对齐辅助线 |
| 拖拽不能改尺寸 | 拖边框改宽高、网格跨列拖拽都还没有 |

## 六、跑起来看看

### 一键演示（推荐先看这个）

```bash
cd jiesu
npm install
npm run build
./scripts/demo.sh            # 起编辑服务 + demo 的 dev server
```

打开 `http://127.0.0.1:5273/` → 按 `Alt+Shift+J` → 点页面上的元素。
左侧 `Alt+Shift+L` 打开图层面板。

换别的靶场：`./scripts/demo.sh spikes/v02/demo`（拖拽）或 `spikes/v01/demo`（属性编辑）。
换端口：`PORT=5300 ./scripts/demo.sh`。

### 接自己的项目

```bash
cd 你的项目
npx jiesu          # 1. 起编辑服务（写 .jiesu/server.json）
npm run dev        # 2. 起你的 dev server
```

要求 `vite.config.ts` 里 `plugins: [jiesu(), react()]`（jiesu 必须在前面）。

### 自己跑测试

```bash
npm test        # 151 个用例：S1 / S2 / S3 / S4 / V0.1~V0.4 端到端 / 打包冒烟
npm run typecheck
npm run build
```

端到端用的是**系统已安装的 Chrome**（`/Applications/Google Chrome.app`），不下载浏览器。
demo 工程：`spikes/v01/demo`（属性编辑）、`spikes/v02/demo`（Shift+拖动排序）、`spikes/v03/demo`（图层面板）、`spikes/v04/demo`（拖动位移）。

> **打包冒烟测试为什么存在**：`npx jiesu` 曾经 100% 起不来，而所有单元测试都是绿的——
> esbuild 的 `banner` 与源码自带的 shebang 叠成了两行 `#!`，Node 只认第一行。
> 这类问题只有"真的执行一次产物"才能发现，所以 `spikes/cli/cli.test.ts` 会真的 spawn 一次。
